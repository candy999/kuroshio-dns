# 快取與本機回答

[← 使用者指南](README.md)

黑潮把查過的答案留在記憶體裡，常用的網站在過期前自動更新；外網斷線時先回舊資料，常用網站照樣連得上。

- **預設**：快取上限依實體記憶體換算，實際大小由記憶體控制依可用記憶體決定。
- **特殊用途網域**（`.invalid`、`.test`、`.onion`、`.example`、`localhost`）在本機直接回答，不問上游。
- **什麼時候要調**：區網真的有用 `.test` 這類網域（例如實驗環境）時，關掉「特殊用途網域在本機回答」。

## 設定

| 設定鍵 | 預設 | 說明 |
|---|---|---|
| `resolver.cacheMax` | `auto` | 快取最多幾筆：實體記憶體的 8% ÷ 每筆約 600 bytes，最少 4,000、最多 100 萬；填數字照填的 |
| `resolver.specialUse` | `true` | 特殊用途網域在本機回答（設定頁「進階」；OpenWrt：`special_use`） |
| `resolver.serveStaleSec` | `3600` | 外網斷線時，過期的答案最多再用多久 |
| `resolver.warmNames` | `2000` | 開機預熱最多幾個常用網域 |

`resolver.cacheMax` = `auto` 換算出來的上限：

| 實體記憶體 | 快取上限 |
|---|---|
| 64 MB | 約 8,900 筆 |
| 128 MB | 約 1.8 萬筆 |
| 448 MB | 約 6.3 萬筆 |
| 1 GB | 約 14.3 萬筆 |
| 8 GB 以上 | 100 萬筆 |

## 怎麼運作

- **依 TTL 快取**，失敗結果也快取；熱門網域在過期前自動更新（自適應預取）。
- **記憶體吃緊時縮小**：最少留上限的 1/8（256～4,096 筆）；「只轉送」時最多 512 筆。見[記憶體與可靠性](memory-and-reliability.md)。
- **開機預熱**：重開機、原地重新啟動、或上游與解析的設定改了（快取重新開始）時，自動預熱常用網域（`hot-names.json`）。
  - 名單只收正常有答案、至少命中 2 次的名稱；同一個網站最多 8 筆、同一個託管平台最多 32 筆，不會被一次性的隨機子網域塞滿。
  - 寫出時跟上一份合併：這次開機常用的排前面，7 天內出現過的接在後面。
  - 只是重新載入設定、接手了上一輪的快取時不預熱。
- **斷線回舊資料**：外網斷線時先回舊資料，常用網站照樣連得上。
- **DNSSEC**：DNSSEC 查詢（DO / CD）與不同類別分開快取；要求 DNSSEC 的查詢原樣轉交上游的答案，不做 CDN 改寫，簽章不會被改壞（本機不驗證 DNSSEC）。
- **特殊用途網域**：依 RFC 6761 本來就不存在的 `.invalid`、`.test`、`.onion`、`.example` 直接回「不存在」，`localhost` 回本機位址（127.0.0.1／::1），不問上游、不算進排行。`example.com`、`example.net` 是一般網域，照常解析。OpenWrt 把區網網域轉給 dnsmasq 的設定照樣優先。
- **同一個名稱同時只問一次**：同一個網域＋類型同時只往上游問一次，其他人等那一次的結果；每個往上游問的工作有總期限 12 秒，逾時回 SERVFAIL、下一筆重新問。
- **IP 測速排序**：上游答案的 IP 用 TCP 測速排序；名額不夠時不排隊，照上游的順序回答。
