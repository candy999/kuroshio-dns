黑潮 DNS 3.3.0：小記憶體路由器更穩（每日評測的記憶體高峰大幅降低、可以要求先讓出記憶體），並加上第三方韌體整合需要的幾個介面。也包含沒有單獨發布的 3.2.1 的修正（LuCI 快取到舊頁面、每次重新啟動都重建節點池）。設定格式不變，直接覆蓋升級即可。

## 修正

- **每日評測期間記憶體暴增**：評測要測約 700 個加密 DNS 候選、每個測 135 個網域。以前每個網域問一輪全部候選，整段評測（最長 150 分鐘）每個候選的連線都一直開著，QUIC 還會定時送 keep-alive，連線不會自己關。Padavan 實測在 Newifi D3 上，評測期間記憶體從 20 MB 漲到 96 MB，128 MB 的機器可能撐不住。現在每個候選用自己的連線依序測完全部網域就關閉，同時開著的連線只有「並行數」那麼多（預設每核心 8 個，也不超過可用記憶體換算的數量）；系統吃緊、評測暫停時先關掉手上的連線。判斷規則（封殺、汙染、逾時淘汰）跟以前相同。評測進度會顯示在狀態頁的排程裡。（Padavan 實機回報）
- **日誌一直出現 `duplicate reset token`**：這是 QUIC 函式庫內部的警告，跟查詢結果無關，但某些伺服器會讓它每十幾秒出現一行，把路由器很小的 syslog 洗掉。現在預設只記這個函式庫的錯誤（`KUROSHIO_LOG` 可以改）。（Padavan 實機回報）
- **LuCI「恢復預設清單」按了沒有反應**（3.2.1）：LuCI 載入外掛的介面檔案時用固定的版本參數，升級後瀏覽器可能還拿到快取裡的舊檔案（Ctrl+F5、清除 Local Storage 都不一定有用）。黑潮 LuCI 頁面的檔案換到新的位置（`view/kuroshio_ui/`、`kuroshio/ui.js`），升級後一定下載新檔案；之後的版本另有版本標記，發現快取到舊檔案會自動重新下載並重新整理一次。
- **每次重新啟動都重建 CDN 節點池**（3.2.1）：節點池存成壓縮檔 `cdn/pools.json.zst`，但「缺檔就補跑」只找 `cdn/pools.json`，每次重新啟動都多花幾分鐘 CPU 重建。現在壓縮檔也算有。（Padavan 實機回報）

## 新功能

- **先讓出記憶體**：`kuroshio notify trim`（或 `POST /api/memory/trim`）立刻縮小快取、把 CDN 冷資料移出記憶體（不停用過濾清單），並在幾分鐘內不再長大。給韌體在很佔記憶體的操作（例如韌體更新把映像檔寫進 tmpfs）之前呼叫。
- **沒有 PSI 的舊核心量得更勤**：沒有 `/proc/pressure` 時只能輪詢可用記憶體，離保留量很遠時從 30 秒一次改成 10 秒，接近時（多不到 64 MB）每 3 秒。
- **狀態裡的記憶體分項**：`/api/status` 的 `memory.sizes` 多了 DNS 快取、CDN 網域資料庫的估計用量；快照目錄在 tmpfs 時顯示快照檔佔的記憶體（`memory.stateInRam`）。
- **立即更新過濾清單改成背景執行**：慢的路由器下載清單可能超過一分鐘，介面或轉接程式會逾時。現在立刻回應，介面等到這一次完成才顯示結果。給整合程式：管理 API 版本 `api` 變成 2，`POST /api/filter/update` 回 `runId`，結果在 `/api/status` 的 `filter.update`；腳本要等結果可以加 `?wait=1`（舊的行為）。
- **寫入設定後執行外部指令**：環境變數 `KUROSHIO_ON_CONFIG_WRITE`（例如 Padavan 的 `mtd_storage.sh save`）。黑潮寫入設定目錄（自訂規則、`.bak` 等；不含學習資料）之後合併執行一次，結束服務前也會先跑完。只能用環境變數設定。
- **介面共用邏輯**：`data/shared/ui-core.js`（全域物件 `KuroshioUiCore`）：恢復預設清單的比對、時間與大小的格式化。LuCI 與 Windows 設定頁都用這一份，第三方韌體的介面可以直接引用，附輸入與預期輸出的測試資料。
- **Linux 通用包附預設設定**：`kuroshio-linux-*.tar.gz` 裡多了 `data/kuroshio.config`（預設 UCI 設定）與 `config.example.json`，升級時只要核對一個檔案。
- **大清單（預設不勾選）**：過濾清單最後多了四份，給記憶體多、要更完整的廣告與資安防護（例如企業）的人自己打開。升級時會加在清單最後、維持不勾選，不影響原本的過濾與記憶體。

壓縮檔裡有 `kuroshio`、`luci-app-kuroshio` 與一鍵安裝腳本：解壓後把資料夾傳到路由器，執行 `sh install.sh`。腳本會先檢查架構與版本，不符合就告訴你該下載哪一個。裝好後到 LuCI「服務 → 黑潮 DNS」確認設定、按「啟用」。

**Windows 10 / 11**：`kuroshio-windows-x86_64.zip`，單一執行檔，不需要另外安裝 Visual C++ 執行階段。

**其他 Linux、第三方路由器韌體**：`kuroshio-linux-<CPU>.tar.gz`（執行檔＋`data/`），見 [移植指南](https://github.com/candy999/kuroshio-dns/blob/main/PORTING.md)；只要執行檔的話是 `kuroshio-<CPU>`。`SHA256SUMS` 是所有檔案的雜湊值。

**原始碼**：`kuroshio-dns-3.3.0-source.tar.xz`（這個版本的原始碼加上全部依賴套件，可以完全離線編譯；雜湊值在 `SHA256SUMS`）。

## 從 3.2.0 升級

- **OpenWrt**：下載同一個架構的新壓縮檔，解壓後執行 `sh install.sh`，直接覆蓋升級。升級後如果 LuCI 選單點了黑潮 DNS 的頁面出現錯誤，登出再登入一次（讓 LuCI 重新讀取選單）。
- **Windows**：停止黑潮 DNS（cmd 視窗輸入 `quit`，或 `kuroshio.exe service stop`），用新的 `kuroshio.exe` 與 `data\` 取代舊的，再啟動。
- **Docker**：`docker compose pull && docker compose up -d`（或 `docker pull ghcr.io/candy999/kuroshio-dns:3.3.0`）。
- **其他 Linux、第三方韌體**：執行檔與 `data/` 一起換。整合程式如果呼叫 `POST /api/filter/update` 並讀回應裡的 `changed`，請改成加 `?wait=1`，或依 `runId` 讀 `/api/status` 的 `filter.update`。

從 3.1.x 或更早升級的說明（預設過濾清單更新、搬移方式）見 [v3.2.0](https://github.com/candy999/kuroshio-dns/releases/tag/v3.2.0)。
