黑潮 DNS 3.5.0（開發中）：每日評測不再冤枉好的加密 DNS，DoH3 的請求修正。

重點：
- **連不上網站不是 DNS 的錯，照常計分**：好幾家互相獨立的加密 DNS 都給同樣的答案、或多家 CDN 的網域，網站連不上時照常計分、今天照用。以前「不記可疑但今天不用」，一個網域就讓幾十台正常的 DNS 整天出局。
- **DoH3 的請求帶 `content-length`**：跟 DoH（HTTP/2、HTTP/1.1）一樣。以前沒帶，部分伺服器回 400／405，好的 DoH3 端點在資格賽就被淘汰。

## 每日評測

- **「網站無法驗證」但不是那台 DNS 的錯時，照常計分**：padavan-tw 3.3.7 的評測裡，一個多家 CDN 的網域在 D3 那條線路連不上（TIMEOUT、ENETUNREACH），41 台回答同一批位址的加密 DNS（包含台灣、日本的大型公共 DNS）因此「今天不用」，當天最後只選出 5 台。這兩種情況本來就判定為網站或路徑的問題、不記可疑，現在也不再淘汰：
  - 同一個業者群組有 3 家以上互相獨立的加密 DNS 都這樣回答。
  - 這個網域已經有 2 家以上不同業者的回答憑證有效（多家 CDN）。
  - 照常計分的方式跟「正常的回答也無法用憑證驗證」一樣：延遲照算，回答的位址照樣算進覆蓋。
  - `judge.log` 寫成「[保留] … 照常計分、不記可疑」，每一題的結算多一項「連不上但照用」。
  - 只有單獨一台（或同一家的幾台）回答連不上的位址時照舊：今天不用，不同的 3 天都這樣才列入永久黑名單。憑證不符的照舊。

## 上游

- **DoH3 帶 `content-length`**：HTTP/3 的函式庫不會自己補這個標頭，DoH（HTTP/2、HTTP/1.1）一直都有帶。沒帶時部分伺服器回 400 Bad Request 或 405 Method Not Allowed：padavan-tw 3.3.7 的評測裡，同一批伺服器的 DoH 都正常，DoH3 卻全部在資格賽失敗。每日評測與執行時的 DoH3 上游都受影響。

## 驗證

- 新增測試：DoH3 請求帶 `content-length`、`content-type`、`accept`；兩種「照常計分」的情況今天照用、不記可疑，同一家的兩台照舊今天不用。
