## 每日評測與預設名單

- **讀出名單的標記（分級、經營者）**：預設名單每一筆本來就寫了整理時的資料（A／B 級、經營者、延遲），但評測只取網址、其餘都丟掉，一般 DNS（`iplist.txt`，資料寫在上一行的註解）更是完全沒有分級。現在每個候選都帶著標記走完評測，`upstreams.json` 的 `selected[]` 多 `tier`、`op`，`counts` 多 `byTier`，報表多 `Tier` 欄。這一步只是讀出來，不改變選誰；分級評測、對照組這些之後的功能要用它。標記不能讓候選跳過任何檢查；使用者自己加、沒寫標記的是 `user`，好友給的一律是 B（不能靠別人的話升到 A）。
- **第一次啟動的初始上游改用預設名單的 A 級**：以前全新安裝時，初始上游是種子資料裡的評測結果——那是 11 月某一天、某一條線路上的結果（5 台平均 49～147 ms，多半是個人架設的 DoH 與遠處的一般 DNS，還帶著那條線路的固定上游與封殺清單），要等第一次評測（啟動後 5 分鐘起、排在 CDN 網段掃描後面）才換掉。現在 `state/upstreams.json` 還是空的時，從預設名單的 A 級挑：依名單的延遲、同一個經營者只取 1 台、加密的優先（還沒做路徑檢查，不知道一般 DNS 有沒有被接走），取 `upstream.autoMax` 台，另外 3 台候補。只讀名單、不先查詢任何伺服器，所以第一次啟動不會一下子對一大批伺服器發查詢；一樣受暫停保護，評測完成就被取代。種子資料裡的上游評測結果拿掉了，CDN 的節點池、IPv6 節點、網域驗證紀錄照舊。已經有評測結果的（升級）不受影響。

## 小修正

- **CDN 關掉時，`/api/status` 的 `cdn` 是 `{"enabled": false}`**：以前是 `null`，看不出是關掉還是讀不到（D3 3.4.3 回報）。
- **記憶體控制讓出不到 1 KB 的步驟不寫 WARN**：例如快取本來就是空的時，「縮小 DNS 快取（約 0 KB）」。只收 WARN 日誌的小機器上這些是雜訊；改成除錯等級（D3 3.4.3 回報）。
- **追蹤網域時標出「被閘道接走」的一般 DNS**：一般 DNS 在路上被路由器攔下時，`/api/trace` 每個上游多 `viaInterceptor`、`note`，表示回答的其實是攔截者，不是那個位址（D3 3.4.2 回報：1.0.0.2、8.8.4.4 其實都是主路由器在回答）。
