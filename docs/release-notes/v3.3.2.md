黑潮 DNS 3.3.2：修正第三方韌體（Padavan）整合時遇到的問題、新增不需要 `uci` 指令的設定檔遷移，並依 padavan-tw 團隊的完整程式審查，補強公網服務的防護、清單更新與寫入。3.3.1 沒有單獨發布，內容都在這一版。設定格式相容，直接覆蓋升級即可；行為有改變的地方列在最前面。

## 升級前請先看

- **存取控制的台灣 IP 資料讀不到時，改成擋下公網來源**：以前資料檔壞掉或讀不到時「全部放行」（fail open），對外的 DoT / DoH / DoQ 會變成全球都能用。現在非開放模式時公網來源一律擋下，區網、社群好友、自訂允許照常；狀態的警告與 `/api/status` 的 `access.failClosed` 看得到。`access.failOpen` 保留給舊的整合，永遠是 `false`。安裝包都附有資料檔，正常安裝不會碰到。
- **每個來源的加密連線數有上限**：新設定 `system.maxTlsConnectionsPerIp`（預設 `auto` = 總上限的 1/8，8～64 條；`0` = 不限），IPv6 以 /64 算一個來源，本機（反向代理）不算。一台主機不能再佔滿全部連線。DoQ / DoH3 等握手完成才計入。
- **設定頁登入網址改用一次性登入碼**：`kuroshio url`、cmd 視窗的 `url` / `open` 印出的是 `/login?code=…`（10 分鐘內有效、只能用一次），長期的 token 不會再留在瀏覽器歷史。`kuroshio url` 會向執行中的服務換登入碼；服務沒在執行時改提示在登入頁貼上 token。舊的 `/login?token=` 網址照樣可以用。

## 公網服務防護

- **DoT**：一條連線同時處理中的查詢最多 64 筆，滿了先不讀下一筆（對方只送不收時不會無限堆積）；送了長度卻不送內容的，10 秒後關閉；回應 30 秒送不出去也關閉；記憶體吃緊時閒置連線 5 秒就關。
- **DoH**：HTTP 標頭要在 10 秒內送完；HTTP/2 每條連線最多 64 個同時進行的請求，定時 ping 清掉斷線的連線。
- **DoQ / DoH3**：每個來源的名額等 QUIC 握手完成（確認來源位址是真的）才計入，偽造來源的封包佔不到真實使用者的名額；還沒驗證的握手太多時，先要求對方驗證位址（QUIC Retry），平常不多一次往返。

## 修正

- **重新載入失敗時服務會結束**：用 `--uci` 執行、收到 SIGHUP 時，新設定讀不進來或啟動不了（例如埠號被佔用），以前會直接結束、等於斷網。現在兩種設定方式都會記錄錯誤、繼續用上一份可以用的設定跑；原因會出現在狀態的警告與 `/api/status` 的 `reload`，下一次重新載入成功就清掉。設定檔改不回上一份（例如唯讀）時也不會結束。（Padavan 回報）
- **服務還在啟動時收到的 SIGHUP 會被略過**：現在記下來，啟動完成後補做一次。
- **寫入設定後的外部指令（`KUROSHIO_ON_CONFIG_WRITE`）**：
  - 自訂規則放在別的地方（例如 Padavan 的 `/etc/storage/kuroshio`）時不會觸發：現在也監看設定裡指到的自訂規則、憑證、社群金鑰、設定頁 token 所在的資料夾，以及 `KUROSHIO_ETC`。（Padavan 回報）
  - 社群金鑰、身分、邀請碼的寫入不會觸發：Padavan 上斷電後社群身分就沒了。現在也會觸發。
  - 指令留下背景程式（例如 `save.sh &`）時一直等它的輸出，之後的寫入都不再觸發：現在指令結束後最多再等 1 秒。
  - 關機前的等待期限只夠跑一次；啟動失敗時不會先跑完：都已修正。
- **第一次載入過濾清單有清單下載失敗時，用不完整的過濾器跑 24 小時**：現在改成 1、2、5 分鐘後重試，之後每 30 分鐘，全部成功才回到正常間隔；下載前先等系統對時（路由器開機時鐘常是 1970）；下載失敗的清單會出現在狀態的警告裡。
- **連線中途斷掉的清單被當成下載完成**：新下載的規則數比上次少一半以上（上次至少 1000 條）時，當成下載不完整，不換上、也不存成副本，有本機副本就用副本。
- **快照一個檔寫失敗，整輪就中止**：現在失敗的那份留著下次再試，其他照常寫。
- **小 Flash 上清單副本每天寫了又刪**：副本實際大小放不下就不存；存副本時只刪日誌讓位，不刪別的清單副本；放不下的不留在記憶體，也不撐大儲存空間的保留量。開機時有幾份副本就先用幾份，沒有副本的稍後下載（以前要全部都有副本才用）。
- **完整備份匯入**：
  - 本機已經有壓縮過的 CDN 候選 IP、IP 網段分類時，會被備份裡的舊資料蓋掉：已修正。
  - 合併後的網域資料庫改成壓縮後寫入。
  - 部分項目寫入失敗時：`kuroshio import` 結束碼改成 1；備份檔改名成 `.failed` 留著，不會整個不見。
  - 設定頁的大檔匯入同時只收一個，大小也不超過可用記憶體的 1/4；狀態目錄空間不夠時先拒絕。
- **UCI 設定**：
  - 同名的區段以前後面整段取代前面的，現在跟 libuci 一樣合併。
  - 埠號沒有範圍檢查（70000 會變成 4464）：範圍外改用預設值並警告。
  - 數字填錯（例如 `5k`、`1e5`）時，以前會默默改用預設值，現在會記警告。
  - `community.max_bundle_mb`、`jobs.tw_ip.max_mem_kb` 對不到設定欄位，設了沒有效果：已修正。
  - 自備憑證只填 cert 或只填 key 時，會跟 acme 位置的另一半配在一起：現在要兩個都填才用，否則警告。
- **`kuroshio uci-migrate` 與 OpenWrt 升級腳本**：`lists_version` 改成比版本大小（以前降版或更新的版本號會重做 3.2 的遷移、把使用者刪掉的清單加回來）；`option enabled ''` 算啟用、重複的選項取最後一個，跟 `uci` 指令一致。
- **其他**：
  - 每日評測被強制結束時，進度會清掉，ASN 快取與可疑紀錄也會存下來。
  - 開機用的 DNS 快取設了上限；探測用的 TLS 連線不留 session 快取。
  - 暫存檔名改成「原檔名.tmp」，不同副檔名的檔案不會共用；改名後也 fsync 資料夾，斷電時才不會回到舊檔。
  - 記憶體控制改用單調時鐘：系統時間往回調時，「先讓出記憶體」的保留時間不會被拉長。
  - `kuroshio notify` 讀不到設定、改用預設管理埠時不帶 token。

## 改善

- **重新載入設定時保留 DNS 快取**：上游、解析、CDN 這類設定沒變時，存檔後不必重新問上游；只改了過濾設定時，丟掉有 CNAME 的項目（查詢網域本身的封鎖一定用新的規則判斷）。
- **清單更新不重複下載**：檢查有沒有更新時，有變的那份不先整份下載；沒變而且有本機副本的直接讀副本。
- **清單重建的記憶體尖峰算進預算**：建置中每條規則約 16 bytes，加上新舊兩份並存，要放得進保留量以上的空間（128 MB 的機器載大清單時才會碰到）；也依上次的規則數先預留，不靠倍增。開機那次就能用副本記的規則數估計。
- **記憶體控制不會卡住記憶體監看**：控制另外一個工作執行，重建清單期間壓力訊號照常更新。
- **CDN 的三個背景工作**（範圍、網段分類、節點池）跟每日評測一樣，記憶體吃緊時在檢查點暫停。
- **關機時記錄寫了幾份快照、多少、花多久**，整合方可以依這個決定停止服務時要等多久。

## 新功能

- **`kuroshio uci-migrate`**：UCI 設定檔的升級遷移，直接改文字檔，不需要 `uci` 指令。規則跟 OpenWrt 套件升級時做的一樣：依 `main.lists_version` 更新沒動過的預設過濾清單、在最後加上新版本預設不勾選的大清單，使用者改過的項目不動，做過的不再做。第三方韌體升級黑潮 DNS 時執行一次即可（`--dry-run` 只顯示會做什麼）。請明確給使用者設定檔的路徑。
- **狀態裡的背景工作用量**：`/api/status` 的 `memory.jobs` 顯示執行中的背景工作，以及每日評測手上的原始答案大小（估計）與開著的連線數，工作結束後回到 0。
- **`POST /api/login-code`**：用 token 換一次性登入碼（給整合方產生登入網址用）。

壓縮檔裡有 `kuroshio`、`luci-app-kuroshio` 與一鍵安裝腳本：解壓後把資料夾傳到路由器，執行 `sh install.sh`。腳本會先檢查架構與版本，不符合就告訴你該下載哪一個。裝好後到 LuCI「服務 → 黑潮 DNS」確認設定、按「啟用」。

**其他 Linux、第三方路由器韌體**：`kuroshio-linux-<CPU>.tar.gz`（執行檔＋`data/`），見 [移植指南](https://github.com/candy999/kuroshio-dns/blob/main/PORTING.md)；只要執行檔的話是 `kuroshio-<CPU>`。`SHA256SUMS` 是所有檔案的雜湊值。

**原始碼**：`kuroshio-dns-3.3.2-source.tar.xz`（這個版本的原始碼加上全部依賴套件，可以完全離線編譯；雜湊值在 `SHA256SUMS`）。

## 從 3.3.0 升級

- **OpenWrt**：下載同一個架構的新壓縮檔，解壓後執行 `sh install.sh`，直接覆蓋升級。
- **Windows**：停止黑潮 DNS（cmd 視窗輸入 `quit`，或 `kuroshio.exe service stop`），用新的 `kuroshio.exe` 與 `data\` 取代舊的，再啟動。
- **Docker**：`docker compose pull && docker compose up -d`（或 `docker pull ghcr.io/candy999/kuroshio-dns:3.3.2`）。
- **其他 Linux、第三方韌體**：執行檔與 `data/` 一起換；用 UCI 文字設定檔的，升級後執行一次 `kuroshio uci-migrate <UCI 檔>`。
