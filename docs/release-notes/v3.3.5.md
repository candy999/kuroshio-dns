黑潮 DNS 3.3.5：修正 OpenWrt 系統升級（sysupgrade）時黑潮 DNS 的設定不會保留的問題。**用 OpenWrt、而且已經裝了 3.3.4 的，請在下一次升級韌體之前先換成 3.3.5。** 程式與設定格式跟 3.3.4 相同。

## 修正

- **OpenWrt 系統升級時設定不會保留**（3.3.4 造成；發布檢查時發現）：
  - 原因：3.3.4 把預設設定移出套件後，OpenWrt 的打包工具會把套件裡沒有的路徑從設定檔清單（conffiles）拿掉，清單變成空的，系統升級（保留設定）時就不會留下 `/etc/config/kuroshio`。
  - 修法：改用 OpenWrt 正式的保留清單 `/lib/upgrade/keep.d/kuroshio`，跟套件裡有沒有這個檔無關。
  - 另外也補上以前就沒保留到的檔案：自訂規則（含 `.bak`）、自己的評測名單、自備憑證、社群身分與好友。以前只保留 `/etc/config/kuroshio`。
  - 學習資料（`/etc/kuroshio/state`：CDN 驗證紀錄、節點池、清單副本等）可能有好幾 MB，系統升級時會佔記憶體，所以不列進保留清單。要留著請先用「備份與分享」匯出，或把資料目錄（`main.data_dir`）改到外接儲存。
  - 一般的套件升級（opkg / apk）不受影響：設定本來就留著，3.3.4 修好的 `resolve_conffiles` 訊息也不會再出現。
  - CI 的 OpenWrt 實機測試加上檢查：保留清單有設定檔與自訂規則；容器裡跑得了 `sysupgrade -l` 時，確認真的會保留。
- **原始碼包少了 Windows 的靜態連結設定**（3.3.0 起）：
  - 原因：產生原始碼包時，`cargo vendor` 的設定蓋掉了 repo 原本的 `.cargo/config.toml`，用原始碼包在 Windows 自己編譯時少了 `+crt-static`。
  - 修法：改成接在後面，產生時也會檢查 `+crt-static` 還在。

## 下載哪一個

**OpenWrt**：在路由器執行 `cat /etc/openwrt_release`，依 `DISTRIB_RELEASE`（OpenWrt 版本）與 `DISTRIB_ARCH`（套件架構）下載 `kuroshio-openwrt-<版本>-<架構>.zip`。

| 平台 | 常見晶片 | 檔名結尾 |
|---|---|---|
| 64 位元 ARM | MediaTek Filogic（MT7981 / MT7986 / MT7988）、MT7622、Qualcomm IPQ807x / IPQ60xx / IPQ50xx、樹莓派 3 | `aarch64_cortex-a53` |
| | Rockchip RK3328 / RK3399 / RK3568 / RK3588（NanoPi R2S～R6S） | `aarch64_generic` |
| | 樹莓派 4、Marvell Armada 7K / 8K | `aarch64_cortex-a72` |
| | 樹莓派 5 | `aarch64_cortex-a76` |
| 32 位元 ARM | Qualcomm IPQ4018 / IPQ4019、Allwinner H3 | `arm_cortex-a7_neon-vfpv4` |
| | Marvell Armada 385（Linksys WRT 系列） | `arm_cortex-a9_vfpv3-d16` |
| | Qualcomm IPQ806x（Netgear R7800 等） | `arm_cortex-a15_neon-vfpv4` |
| MIPS | MediaTek MT7621 / MT7620 / MT7628（小端序） | `mipsel_24kc` |
| | Qualcomm Atheros、Lantiq（大端序） | `mips_24kc` |
| x86 | 軟路由小主機、虛擬機 | `x86_64` |

OpenWrt 24.10 用 `-24.10-` 的（.ipk），25.12 以後用 `-25.12-` 的（.apk）。不知道選哪個：[選硬體](https://github.com/candy999/kuroshio-dns/blob/main/docs/hardware.md)。

壓縮檔裡有 `kuroshio`、`luci-app-kuroshio` 與一鍵安裝腳本：解壓後把資料夾傳到路由器，執行 `sh install.sh`。腳本會先檢查架構與版本，不符合就告訴你該下載哪一個。裝好後到 LuCI「服務 → 黑潮 DNS」確認設定、按「啟用」。

**Windows 10 / 11**：`kuroshio-windows-x86_64.zip`，單一執行檔，不需要另外安裝 Visual C++ 執行階段。

**Docker**：`docker pull ghcr.io/candy999/kuroshio-dns:3.3.5`，見 [Docker 使用說明](https://github.com/candy999/kuroshio-dns/blob/main/docs/docker.md)。

**其他 Linux、第三方路由器韌體**：`kuroshio-linux-<CPU>.tar.gz`（執行檔＋`data/`），見 [移植指南](https://github.com/candy999/kuroshio-dns/blob/main/PORTING.md)；只要執行檔的話是 `kuroshio-<CPU>`。`SHA256SUMS` 是所有檔案的雜湊值。

**原始碼**：`kuroshio-dns-3.3.5-source.tar.xz`（這個版本的原始碼加上全部依賴套件，可以完全離線編譯；雜湊值在 `SHA256SUMS`）。

## 從 3.3.4 升級

- **OpenWrt**：下載同一個架構的新壓縮檔，解壓後執行 `sh install.sh`，直接覆蓋升級。
- **Windows**：停止黑潮 DNS（cmd 視窗輸入 `quit`，或 `kuroshio.exe service stop`），用新的 `kuroshio.exe` 與 `data\` 取代舊的，再啟動。
- **Docker**：`docker compose pull && docker compose up -d`（或 `docker pull ghcr.io/candy999/kuroshio-dns:3.3.5`）。
- **其他 Linux、第三方韌體**：執行檔與 `data/` 一起換；用 UCI 文字設定檔的，升級後執行一次 `kuroshio uci-migrate <UCI 檔>`。

從更早的版本升級，先看 [v3.3.4](https://github.com/candy999/kuroshio-dns/releases/tag/v3.3.4)、[v3.3.3](https://github.com/candy999/kuroshio-dns/releases/tag/v3.3.3) 與 [v3.3.2](https://github.com/candy999/kuroshio-dns/releases/tag/v3.3.2) 的說明。
