黑潮 DNS 3.3.6：**路徑檢查**。分辨「上游壞了」和「路上有人動手腳」：不管是上游路由器的黑潮、業者的透明代理把 53 埠接走，還是 DoT / QUIC 被擋、沒有 IPv6，評測和上游選擇都照實際的路調整，不再冤枉正常的 DNS。依 padavan-tw 在 Newifi D3（接在另一台跑黑潮的主路由器後面）的實測資料修正。

## 為什麼要做

padavan-tw 11-18～19 的資料：D3 的一般 DNS（53 埠）全部被主路由器的黑潮接走，那天又沒有 IPv6。

- 11-19 的評測裡，306 台一般 DNS 候選（1.1.1.1、8.8.8.8、168.95.1.1…）全部在 `s-gm.mmstat.com` 被判「封殺」。那不是它們在過濾，而是主路由器的黑潮用自己的廣告過濾在回答。在那之前的幾題，這 306 票其實都是同一個攔截者投的。
- 11-18 有 15 台正常的加密 DNS（Cloudflare、dns.sb、IIJ、rethinkdns、dnscry.pt…）被記成「可疑」一天。
- 沒有 IPv6 時，DoQ / DoH3 一直試 IPv6 位址，系統記錄出現 `sendmsg error: AddrNotAvailable`。

## 新功能：路徑檢查

啟動後、每 6 小時、`kuroshio notify wan-changed` 時各做一次，每日評測開始前也會再做一次。IPv4、IPv6 分開判斷。

| 檢查 | 判斷之後 |
|---|---|
| **一般 DNS 被接走**：對文件用的保留位址（192.0.2.1 等）查詢，有回答就是路上有人把 53 埠全部轉走。UDP、TCP 分開測 | 評測不測一般 DNS；執行時一般 DNS 的回答不拿來合併、不參加多數決；只當最後備援，標成「經由攔截者」 |
| **攔截者是誰**：上游的黑潮（3.3.6 起會回答自己的版本）、一般 DNS 軟體（dnsmasq 等）、不明（業者或其他設備）；預設閘道一起記下 | 狀態頁寫成白話，例如「一般 DNS 被路由器 192.168.1.1 上的黑潮（3.3.6）接走」 |
| **「不存在」被改成廣告頁**、**答案被竄改**（`dns.google`、`one.one.one.one` 的答案不對） | 解析加密上游的主機名稱（bootstrap）改用 IP 直連的 DoH |
| **加密協定整條被擋**：DoT 853、DoH 443、QUIC 各試三台知名伺服器 | 那種上游先不用、評測也不測，路恢復了自動加回 |
| **TLS 中途攔截**：好幾台都出現憑證錯誤 | 顯示提醒（不算協定被擋） |
| **IPv6 能不能用**：不送封包的路由檢查；連線遇到「位址不可用」「網路無法到達」暫停 IPv6 10 分鐘 | 不能用時只用 IPv4（DoT / DoH / DoQ / DoH3 / bootstrap 都一樣），不再出現 `AddrNotAvailable` 警告 |

- 新指令 **`kuroshio check-path [--json]`**：立刻檢查一次並印出結果，不需要服務在跑。
- `/api/status` 新增 `network.path`，有狀況時 `warnings` 裡也有白話提醒；格式見 [整合文件](https://github.com/candy999/kuroshio-dns/blob/main/docs/integration.md#路徑檢查336-起)。
- 狀態頁（LuCI、Windows 設定頁）多了「網路路徑」，上游列表標出每台的角色與選上的原因（最快、覆蓋）、「路徑不通，先不用」、「經由攔截者」。

### 開關

LuCI「進階 → 上游 DNS」、Windows 設定頁（專業模式）、UCI `config upstream 'upstream'`：

| UCI | 預設 | 說明 |
|---|---|---|
| `path_check` | `1` | `0` 整個關掉 |
| `intercept_policy` | `skip-plain` | 一般 DNS 被接走時：`skip-plain` 評測不測一般 DNS；`warn` 只提醒；`ignore` 不理會 |
| `ipv6` | `auto` | 用 IPv6 連上游：`auto` 依路由判斷；`1` 一律使用；`0` 不用（路由器的 IPv6 關閉時可以帶 `0`） |

## 每日評測的判斷

- **一般 DNS 的答案完全一樣時只算一票**：就算沒偵測到攔截，同一個攔截者的幾百票也不會變成「多數」。
- **多家獨立的加密 DNS 一致時不記可疑**：「網站無法驗證」（連不上）的回答，同一個業者有 3 家以上互相獨立的加密 DNS 都這樣回答時，今天不用，但不記可疑天數（比較可能是網站或路的問題）。憑證不符的照舊判定汙染。
- **依路徑略過的候選不記可疑、不進黑名單**，數量記在 `upstreams.json` 的 `pathSkipped`；評測當時的路徑判斷記在 `path`。
- **判斷過程的摘要** `judge.log`（每一題的第一名、淘汰、今天不用的原因）寫進報表目錄。Flash 機器的報表目錄在記憶體裡、重開機就沒了，所以最近一次的 `judge.log`、`eliminated.csv`、`upstreams.json`（各 128 KB 以內）另存到學習資料區的 `benchmark-last/`（`benchmark.keepLastReport: false` 關掉）。

## 其他

- 黑潮 3.3.6 對區網的一般 DNS 回答 CHAOS TXT `version.kuroshio`（`kuroshio/3.3.6`），讓下游的黑潮認出自己；公開的 DoH / DoT 不回答。
- 這台完全沒有 IPv6（連 `::1` 都沒有）時，`[::1]` 綁定失敗改成一般訊息，不再顯示警告。

## 下載哪一個

**OpenWrt**：在路由器執行 `cat /etc/openwrt_release`，依 `DISTRIB_RELEASE`（OpenWrt 版本）與 `DISTRIB_ARCH`（套件架構）下載 `kuroshio-openwrt-<版本>-<架構>.zip`。

| 平台 | 常見晶片 | 檔名結尾 |
|---|---|---|
| 64 位元 ARM | MediaTek Filogic（MT7981 / MT7986 / MT7988）、MT7622、Qualcomm IPQ807x / IPQ60xx / IPQ50xx、樹莓派 3 | `aarch64_cortex-a53` |
| | Rockchip RK3328 / RK3399 / RK3568 / RK3588（NanoPi R2S～R6S） | `aarch64_generic` |
| | 樹莓派 4、Marvell Armada 7K / 8K | `aarch64_cortex-a72` |
| | 樹莓派 5 | `aarch64_cortex-a76` |
| 32 位元 ARM | Qualcomm IPQ4018 / IPQ4019、Allwinner H3 | `arm_cortex-a7_neon-vfpv4` |
| | Marvell Armada 385（Linksys WRT 系列） | `arm_cortex-a9_vfpv3-d16` |
| | Qualcomm IPQ806x（Netgear R7800 等） | `arm_cortex-a15_neon-vfpv4` |
| MIPS | MediaTek MT7621 / MT7620 / MT7628（小端序） | `mipsel_24kc` |
| | Qualcomm Atheros、Lantiq（大端序） | `mips_24kc` |
| x86 | 軟路由小主機、虛擬機 | `x86_64` |

OpenWrt 24.10 用 `-24.10-` 的（.ipk），25.12 以後用 `-25.12-` 的（.apk）。不知道選哪個：[選硬體](https://github.com/candy999/kuroshio-dns/blob/main/docs/hardware.md)。

壓縮檔裡有 `kuroshio`、`luci-app-kuroshio` 與一鍵安裝腳本：解壓後把資料夾傳到路由器，執行 `sh install.sh`。腳本會先檢查架構與版本，不符合就告訴你該下載哪一個。裝好後到 LuCI「服務 → 黑潮 DNS」確認設定、按「啟用」。

**Windows 10 / 11**：`kuroshio-windows-x86_64.zip`，單一執行檔，不需要另外安裝 Visual C++ 執行階段。

**Docker**：`docker pull ghcr.io/candy999/kuroshio-dns:3.3.6`，見 [Docker 使用說明](https://github.com/candy999/kuroshio-dns/blob/main/docs/docker.md)。

**其他 Linux、第三方路由器韌體**：`kuroshio-linux-<CPU>.tar.gz`（執行檔＋`data/`），見 [移植指南](https://github.com/candy999/kuroshio-dns/blob/main/PORTING.md)；只要執行檔的話是 `kuroshio-<CPU>`。`SHA256SUMS` 是所有檔案的雜湊值。

**原始碼**：`kuroshio-dns-3.3.6-source.tar.xz`（這個版本的原始碼加上全部依賴套件，可以完全離線編譯；雜湊值在 `SHA256SUMS`）。

## 從 3.3.5 升級

- **OpenWrt**：下載同一個架構的新壓縮檔，解壓後執行 `sh install.sh`，直接覆蓋升級。新開關的預設值就是建議值，不用改設定。
- **Windows**：停止黑潮 DNS（cmd 視窗輸入 `quit`，或 `kuroshio.exe service stop`），用新的 `kuroshio.exe` 與 `data\` 取代舊的，再啟動。
- **Docker**：`docker compose pull && docker compose up -d`（或 `docker pull ghcr.io/candy999/kuroshio-dns:3.3.6`）。
- **其他 Linux、第三方韌體**：執行檔與 `data/` 一起換；用 UCI 文字設定檔的，升級後執行一次 `kuroshio uci-migrate <UCI 檔>`。

從更早的版本升級，先看 [v3.3.5](https://github.com/candy999/kuroshio-dns/releases/tag/v3.3.5)、[v3.3.4](https://github.com/candy999/kuroshio-dns/releases/tag/v3.3.4)、[v3.3.3](https://github.com/candy999/kuroshio-dns/releases/tag/v3.3.3) 與 [v3.3.2](https://github.com/candy999/kuroshio-dns/releases/tag/v3.3.2) 的說明。
