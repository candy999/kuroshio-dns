黑潮 DNS 3.3.3：每日評測後記憶體會降回來、重新載入設定時 DNS 不再停頓，並新增 `kuroshio memory-plan` 推算各種記憶體大小的機器會怎樣運作。設定格式與 API 跟 3.3.2 相同，直接覆蓋升級即可。

## 修正

- **每日評測後記憶體降不回來**（Padavan 回報）：
  - 現象：評測時 RSS 從約 20 MB 漲到約 45 MB，結束後停在 44 MB，`kuroshio notify trim` 也降不下來。
  - 原因：評測時大量短命的小配置跟同時期的長期資料交錯，記憶體配置器無法把空出來的記憶體還給系統（碎片），跟資料有沒有釋放無關。
  - 3.3.3 起每日評測在子程序裡跑，結束時記憶體全部還給系統，主程式的常駐用量固定。日誌、進度、記憶體吃緊時暫停、排程逾時強制結束都跟以前一樣。
- **重新載入設定時有幾秒 DNS 不回答**（Padavan 回報）：用本機副本重建大清單（例如 37 萬條）時，解壓、解析、建索引都在回答查詢的執行緒上一口氣做完，路由器上會停 4 秒左右。現在解壓與建索引放到另外的執行緒，解析每 64 KB 讓出一次，DNS 與管理 API 照常回應。
- **資格賽期間看不到評測用量**：`memory.jobs` 在資格賽階段也會顯示開著幾條連線；每個候選的連線輪到才建立。
- 第一次啟動、CDN 網域資料庫還是空的時候，日誌不再洗出 256 行「分片不見了」。

## 新功能

- **`kuroshio memory-plan`**：用跟執行時同一套規則（保留量、記憶體壓力、清單預算、評測並行數）推算這台機器，或 `--ram 64 128` 指定大小、`--bits 32` 指定 32 位元的機器：
  - 保留量是多少、黑潮 DNS 常駐用多少；
  - 哪些清單載得進來；
  - 每日評測同時測幾個、會不會暫停。
  
  `--json` 給程式用。服務正在執行時，清單規則數用它實際載入的值。常數用 Padavan（Newifi D3）3.3.3 的實測：推算的常駐 21.7 MB、評測子程序最高 36.5 MB，實測是 21.8 MB、37 MB。README 新增「記憶體用量與小記憶體的機器」一節，表格就是這個指令的輸出。
- **`memory.jobs` 多了評測子程序的實際用量**：`processRssBytes`（目前）、`processPeakRssBytes`（最高）；`lastBenchmark` 留著上一次評測的結果（結束時間、成功與否、花多久、記憶體最高多少），評測結束後也查得到。
- **每日評測同時測幾個，改用實測的每個候選約 512 KB 估**（以前用 128 KB）：記憶體少的機器並行數會少一點，評測期間不會擠到保留量。記憶體多的機器照樣是設定值（預設每核心 8 個，最多 50）。
- 本機清單副本的規則數：3.3.2 以前寫的副本沒有記，3.3.3 起用副本載入時會補記（`memory-plan` 才算得準）。

## 整合方注意

- 每日評測進行中，`ps` 會多看到一個 `kuroshio __job-dns-benchmark`；服務管理程式只要管主程式，主程式結束時子程序會跟著結束。
- 不想要子程序時設 `benchmark.subprocess: false`（照舊在同一個程式裡跑）。

## 下載哪一個

**OpenWrt**：在路由器執行 `cat /etc/openwrt_release`，依 `DISTRIB_RELEASE`（OpenWrt 版本）與 `DISTRIB_ARCH`（套件架構）下載 `kuroshio-openwrt-<版本>-<架構>.zip`。

| 平台 | 常見晶片 | 檔名結尾 |
|---|---|---|
| 64 位元 ARM | MediaTek Filogic（MT7981 / MT7986 / MT7988）、MT7622、Qualcomm IPQ807x / IPQ60xx / IPQ50xx、樹莓派 3 | `aarch64_cortex-a53` |
| | Rockchip RK3328 / RK3399 / RK3568 / RK3588（NanoPi R2S～R6S） | `aarch64_generic` |
| | 樹莓派 4、Marvell Armada 7K / 8K | `aarch64_cortex-a72` |
| | 樹莓派 5 | `aarch64_cortex-a76` |
| 32 位元 ARM | Qualcomm IPQ4018 / IPQ4019、Allwinner H3 | `arm_cortex-a7_neon-vfpv4` |
| | Marvell Armada 385（Linksys WRT 系列） | `arm_cortex-a9_vfpv3-d16` |
| | Qualcomm IPQ806x（Netgear R7800 等） | `arm_cortex-a15_neon-vfpv4` |
| MIPS | MediaTek MT7621 / MT7620 / MT7628（小端序） | `mipsel_24kc` |
| | Qualcomm Atheros、Lantiq（大端序） | `mips_24kc` |

OpenWrt 24.10 用 `-24.10-` 的（.ipk），25.12 以後用 `-25.12-` 的（.apk）。不知道選哪個：[選硬體](https://github.com/candy999/kuroshio-dns/blob/main/docs/hardware.md)。

壓縮檔裡有 `kuroshio`、`luci-app-kuroshio` 與一鍵安裝腳本：解壓後把資料夾傳到路由器，執行 `sh install.sh`。腳本會先檢查架構與版本，不符合就告訴你該下載哪一個。裝好後到 LuCI「服務 → 黑潮 DNS」確認設定、按「啟用」。

**Windows 10 / 11**：`kuroshio-windows-x86_64.zip`，單一執行檔，不需要另外安裝 Visual C++ 執行階段。

**Docker**：`docker pull ghcr.io/candy999/kuroshio-dns:3.3.3`，見 [Docker 使用說明](https://github.com/candy999/kuroshio-dns/blob/main/docs/docker.md)。

**其他 Linux、第三方路由器韌體**：`kuroshio-linux-<CPU>.tar.gz`（執行檔＋`data/`），見 [移植指南](https://github.com/candy999/kuroshio-dns/blob/main/PORTING.md)；只要執行檔的話是 `kuroshio-<CPU>`。`SHA256SUMS` 是所有檔案的雜湊值。

**原始碼**：`kuroshio-dns-3.3.3-source.tar.xz`（這個版本的原始碼加上全部依賴套件，可以完全離線編譯；雜湊值在 `SHA256SUMS`）。

## 從 3.3.2 升級

- **OpenWrt**：下載同一個架構的新壓縮檔，解壓後執行 `sh install.sh`，直接覆蓋升級。
- **Windows**：停止黑潮 DNS（cmd 視窗輸入 `quit`，或 `kuroshio.exe service stop`），用新的 `kuroshio.exe` 與 `data\` 取代舊的，再啟動。
- **Docker**：`docker compose pull && docker compose up -d`（或 `docker pull ghcr.io/candy999/kuroshio-dns:3.3.3`）。
- **其他 Linux、第三方韌體**：執行檔與 `data/` 一起換；用 UCI 文字設定檔的，升級後執行一次 `kuroshio uci-migrate <UCI 檔>`。

從更早的版本升級，先看 [v3.3.2](https://github.com/candy999/kuroshio-dns/releases/tag/v3.3.2) 的「升級前請先看」。
