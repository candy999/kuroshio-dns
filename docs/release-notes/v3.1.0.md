黑潮 DNS 3.1.0：讓黑潮更容易裝到 OpenWrt、Windows 以外的地方。新增 Docker 映像檔、Linux 通用版壓縮包、給其他平台整合用的穩定指令，以及移植指南。DNS、過濾、CDN 的運作跟 3.0.2 相同，直接覆蓋升級即可，設定與學習資料會保留。

## 新功能

- **Docker 映像檔**：`ghcr.io/candy999/kuroshio-dns`（x86_64、ARM64、ARMv7），適合 NAS（群暉、威聯通、Unraid）、VPS、家用伺服器。內建健康檢查，第一次啟動自動建立設定檔，設定與學習資料都在 `/config`。附 Docker Compose 範例，以及搭配 Caddy（自動 HTTPS、HTTP/3）的範例。說明：[Docker 使用說明](https://github.com/candy999/kuroshio-dns/blob/main/docs/docker.md)。
- **Linux 通用版壓縮包** `kuroshio-linux-<CPU>.tar.gz`：執行檔＋同一版的 `data/`，給第三方路由器韌體與不跑 Docker 的 Linux。原本的單一執行檔 `kuroshio-<CPU>` 照舊提供，檔名不變。
- **整合用的指令**（說明：[整合介面](https://github.com/candy999/kuroshio-dns/blob/main/docs/integration.md)）：
  - `kuroshio health`：用結束碼表示有沒有在回答查詢（0 正常、1 沒有回答、2 設定錯誤）。
  - `kuroshio status --json`：版本、上游、快取命中率、過濾規則數、儲存方式、時間是否已對時、`data/` 版本與警告。
  - `kuroshio notify wan-changed`：WAN 換了 IP 時通知黑潮，立即更新 DDNS 並重新偵測公網 IP。
  - 訊號：SIGHUP 重新載入設定、SIGUSR1 立即把學到的資料寫出。
- **時間還沒對時也能用**：沒有硬體時鐘的路由器開機時是 1970 年，加密上游的憑證檢查會失敗。現在偵測到時間不合理時，先只用一般 DNS 上游回答（NTP 也查得到），並暫停需要加密連線的背景工作，不會因此把節點或上游記成失敗；對時後自動恢復。
- **`data/` 版本標記**：`data/manifest.json`。執行檔與 `data/` 版本不一致時，在啟動日誌與 `status --json` 顯示警告（照常提供 DNS）。
- **[移植指南 PORTING.md](https://github.com/candy999/kuroshio-dns/blob/main/PORTING.md)**：一般 Linux、NAS、第三方韌體（梅林、Padavan、DD-WRT…）的做法、儲存策略、接上 dnsmasq、故障退回、檢查清單。另有 [建置說明](https://github.com/candy999/kuroshio-dns/blob/main/docs/building.md)。
- **發布檔可驗證來源**：每個發布檔與映像檔都附 GitHub 的建置來源證明，可以用 `gh attestation verify <檔案> --repo candy999/kuroshio-dns` 確認是由本專案的 CI 編出來的。

## 其他改變

- **自己的網域不會外流**：分享檔（`kuroshio export --share`）與好友同步，不再包含你自己網域（綁定網域的上層網域，例如 `dns.example.net` → `example.net`）底下的名稱。完整備份照舊包含全部（換機用）。
- **Windows：cmd 執行時自動關閉主控台的「快速編輯模式」**：在視窗裡點一下滑鼠不會再讓程式暫停、DNS 卡住。
- OpenWrt 的 DNS 備援（`guard.sh`）改用 `kuroshio health` 判斷。
- 種子資料移除了 3 筆不該包含的個人網域。
- 整理相依套件（Linux 版少編一個用不到的套件）。
- MIPS 版編譯跟著最新的 Rust nightly；最新的編不過時自動改用已知可用的版本，不會因此發布不出來。

## 下載哪一個

**OpenWrt**：在路由器執行 `cat /etc/openwrt_release`，依 `DISTRIB_RELEASE`（OpenWrt 版本）與 `DISTRIB_ARCH`（套件架構）下載 `kuroshio-openwrt-<版本>-<架構>.zip`。

| 平台 | 常見晶片 | 檔名結尾 |
|---|---|---|
| 64 位元 ARM | MediaTek Filogic（MT7981 / MT7986 / MT7988）、MT7622、Qualcomm IPQ807x / IPQ60xx / IPQ50xx、樹莓派 3 | `aarch64_cortex-a53` |
| | Rockchip RK3328 / RK3399 / RK3568 / RK3588（NanoPi R2S～R6S） | `aarch64_generic` |
| | 樹莓派 4、Marvell Armada 7K / 8K | `aarch64_cortex-a72` |
| | 樹莓派 5 | `aarch64_cortex-a76` |
| 32 位元 ARM | Qualcomm IPQ4018 / IPQ4019、Allwinner H3 | `arm_cortex-a7_neon-vfpv4` |
| | Marvell Armada 385（Linksys WRT 系列） | `arm_cortex-a9_vfpv3-d16` |
| | Qualcomm IPQ806x（Netgear R7800 等） | `arm_cortex-a15_neon-vfpv4` |
| MIPS | MediaTek MT7621 / MT7620 / MT7628（小端序） | `mipsel_24kc` |
| | Qualcomm Atheros、Lantiq（大端序） | `mips_24kc` |
| x86 | 軟路由小主機、虛擬機 | `x86_64` |

OpenWrt 24.10 用 `-24.10-` 的（.ipk），25.12 以後用 `-25.12-` 的（.apk）。不知道選哪個：[選硬體、選套件](https://github.com/candy999/kuroshio-dns/blob/main/docs/hardware.md)。

壓縮檔裡有 `kuroshio`、`luci-app-kuroshio` 與一鍵安裝腳本：解壓後把資料夾傳到路由器，執行 `sh install.sh`。腳本會先檢查架構與版本，不符合就告訴你該下載哪一個。裝好後到 LuCI「服務 → 黑潮 DNS」確認設定、按「啟用」。

**Windows 10 / 11**：`kuroshio-windows-x86_64.zip`，單一執行檔，不需要另外安裝 Visual C++ 執行階段。

**Docker**：`docker pull ghcr.io/candy999/kuroshio-dns:3.1.0`，見 [Docker 使用說明](https://github.com/candy999/kuroshio-dns/blob/main/docs/docker.md)。

**其他 Linux、第三方路由器韌體**：`kuroshio-linux-<CPU>.tar.gz`（執行檔＋`data/`），見 [移植指南](https://github.com/candy999/kuroshio-dns/blob/main/PORTING.md)；只要執行檔的話是 `kuroshio-<CPU>`。`SHA256SUMS` 是所有檔案的雜湊值。

## 從 3.0.x 升級

- **OpenWrt**：下載同一個架構的新壓縮檔，解壓後執行 `sh install.sh`，直接覆蓋升級。
- **Windows**：停止黑潮 DNS（cmd 視窗輸入 `quit`，或 `kuroshio.exe service stop`），用新的 `kuroshio.exe` 與 `data\` 取代舊的，再啟動。這一版的 `data\` 多了版本標記，請一起換掉。
- **其他 Linux**：執行檔與 `data/` 一起換。

## 已知限制

- Linux 通用版在第三方路由器韌體上的整合，由各平台維護者自行測試；本專案 CI 實際測試的是 OpenWrt、Windows 與 Docker（x86_64 映像檔）。
