黑潮 DNS 3.4.0：**串接模式**。兩台都跑黑潮時（例如 Newifi D3 接在跑黑潮的主路由器後面），下游會認出上游的黑潮、驗證身分後自動串接，直接用上游的評測結果、CDN 節點池與過濾清單副本，不必每天自己重做。另外加上低階機器的並行數、上游多樣性、重新載入不斷線、補跑時段。

## 串接模式（兩層黑潮）

只有兩個開關，預設都開，**兩邊都開才通訊**，任一邊關就各走各的：

| 開關 | 在哪一台 | 開（預設） | 關 |
|---|---|---|---|
| `chain` | 下游 | 辨識上游黑潮，驗證後自動串接並拿需要的資料 | 一律當成「一般 DNS 被接走的網路」，跟 3.3.7 一樣 |
| `allow_downstream` | 上游 | 提供資料給驗證過的下游黑潮 | 照樣回答「我是黑潮」，但不提供資料。**下游會自己重做評測、CDN 掃描、下載清單，重複使用網路（含這台的頻寬）** |

LuCI「進階 → 上游 DNS」、Windows 設定頁（專業模式）、UCI `config upstream 'upstream'` 都可以設。

- **怎麼認出上游**：接在 3.3.6 的路徑檢查後面。認出「一般 DNS 被上游的黑潮（3.4.0 以上）接走」之後，才發挑戰碼；上游用節點金鑰（Ed25519）簽章回答，每次挑戰都是新的亂數，不能重放。區網其他裝置冒充不了上游。
- **串接中**：上游黑潮是第一順位上游，下游不再同時問自己的加密上游（MT7621 這類機器省下 TLS 的負擔）。上游連續失敗時暫停 30 秒，這段時間改用自己的加密上游。
- **共用結果**：下游直接拿上游的評測結果、CDN 節點池、過濾清單副本（網址相同、下游放得下的才拿），自己的每日評測與 CDN 掃描略過，排程頁顯示「由上游黑潮提供，略過」。拿不到、或上游資料 36 小時沒更新時，自動恢復自己做。
- **上游放行下游**：驗證過、登記中的下游黑潮，上游的「繞過防護」清單（HaGeZi doh-vpn-proxy-bypass）不擋它解析自己上游的主機名稱。登記只在記憶體，最多 16 台、15 分鐘到期，每次都要通過簽章、來源位址、一次性憑據的檢查。
- **自動解除**：上游換掉（金鑰不同）、連續沒回應、`kuroshio notify wan-changed`、路徑檢查發現不再被接走或答案被竄改時解除，退回自己的上游；上游回來會自動接回。上游換了金鑰時自動重新綁定，狀態頁警告保留 24 小時。
- **防迴圈**：每台帶著節點 ID 鏈，A→B→A 不會串起來；最多 4 層。
- **看得到**：狀態頁（LuCI、Windows 設定頁）的「串接」區塊同時顯示兩個角色：這台當下游的狀態，以及這台當上游時連上來的下游（指紋、位址、版本、第一次與最後出現時間）。新指令 `kuroshio chain status [--json]`、`kuroshio chain recheck`；`kuroshio check-path` 多一行串接；`/api/status` 多 `chain`，新 API `/api/chain`。
- **相容**：3.3.x 混著用不會壞。上游是 3.3.x 時，下游顯示「上游黑潮版本太舊」，照 3.3.7 的方式運作；下游是 3.3.x 時，上游照常服務。

## 其他新功能

- **低階機器的並行數**：沒有 AES 硬體加速的 CPU（MT7621、ARMv7 等），`resolver.parallel` 的 `auto` 改成先問最快的 2 個上游；其他上游只對 CDN 相關網域、以及每 16 次抽 1 次的一般網域，在回應用戶端之後背景補問並比對答案（`resolver.backfill`、`resolver.backfillSample`）。有 AES 的機器跟以前一樣。狀態的今日統計多了「背景補問」「答案不一致」。
- **上游多樣性**（`benchmark.coverageRegion`，預設 `near`）：每日評測挑「覆蓋」上游時，先挑台灣、日本、香港、新加坡的，不夠才挑其他地區；依台灣網段、ip-api 的國別、量到的最低延遲判斷。`any` 跟以前一樣。上游清單顯示地區。
- **重新載入不斷線**：一般 DNS、DoT、DoH、DoQ、DoH3 的監聽 socket 留到下一輪接著用，`SIGHUP`（改設定、儲存）之後不再有 0.2～0.4 秒的 Connection refused。
- **補跑時段**（`main.catchup_window`，例如 `'01:00-06:00'`，依 padavan-tw 的建議）：剛刷機、學習資料不見、或很久沒跑時的補跑只在這段時間進行，期間先用預設上游；排定時間與手動執行不受影響。預設空白，跟以前一樣開機後幾分鐘就補跑。

## 修正

- `upstream.autoMax` 設成 `0` 時仍會載入 1 台自動上游。
- 「恢復預設清單」比對不出「繞過防護」標記的差異。
- 3.4.0 之前存下的設定裡的 HaGeZi doh-vpn-proxy-bypass 清單，不用遷移就會被認成「繞過防護」清單。

## 已知限制

- 串接走一般 DNS（不需要上游開加密監聽、下游不必做 TLS），每筆查詢本身沒有驗證：同一個區網裡能做 ARP 欺騙的裝置可以竄改答案。路徑檢查的竄改偵測會解除串接，也可以關掉 `chain`。之後的版本預計加上釘選公鑰的 DoT。
- 區網裡的裝置可以自己架一個下游黑潮來繞過「繞過防護」清單；這沒有絕對擋得住的方法，不想要的話關掉上游的 `allow_downstream`。
- 兩台都要升到 3.4.0 才會串接。

## 下載哪一個

**OpenWrt**：在路由器執行 `cat /etc/openwrt_release`，依 `DISTRIB_RELEASE`（OpenWrt 版本）與 `DISTRIB_ARCH`（套件架構）下載 `kuroshio-openwrt-<版本>-<架構>.zip`。

| 平台 | 常見晶片 | 檔名結尾 |
|---|---|---|
| 64 位元 ARM | MediaTek Filogic（MT7981 / MT7986 / MT7988）、MT7622、Qualcomm IPQ807x / IPQ60xx / IPQ50xx、樹莓派 3 | `aarch64_cortex-a53` |
| | Rockchip RK3328 / RK3399 / RK3568 / RK3588（NanoPi R2S～R6S） | `aarch64_generic` |
| | 樹莓派 4、Marvell Armada 7K / 8K | `aarch64_cortex-a72` |
| | 樹莓派 5 | `aarch64_cortex-a76` |
| 32 位元 ARM | Qualcomm IPQ4018 / IPQ4019、Allwinner H3 | `arm_cortex-a7_neon-vfpv4` |
| | Marvell Armada 385（Linksys WRT 系列） | `arm_cortex-a9_vfpv3-d16` |
| | Qualcomm IPQ806x（Netgear R7800 等） | `arm_cortex-a15_neon-vfpv4` |
| MIPS | MediaTek MT7621 / MT7620 / MT7628（小端序） | `mipsel_24kc` |
| | Qualcomm Atheros、Lantiq（大端序） | `mips_24kc` |

OpenWrt 24.10 用 `-24.10-` 的（.ipk），25.12 以後用 `-25.12-` 的（.apk）。不知道選哪個：[選硬體](https://github.com/candy999/kuroshio-dns/blob/main/docs/hardware.md)。

壓縮檔裡有 `kuroshio`、`luci-app-kuroshio` 與一鍵安裝腳本：解壓後把資料夾傳到路由器，執行 `sh install.sh`。腳本會先檢查架構與版本，不符合就告訴你該下載哪一個。裝好後到 LuCI「服務 → 黑潮 DNS」確認設定、按「啟用」。

**Windows 10 / 11**：`kuroshio-windows-x86_64.zip`，單一執行檔，不需要另外安裝 Visual C++ 執行階段。

**Docker**：`docker pull ghcr.io/candy999/kuroshio-dns:3.4.0`，見 [Docker 使用說明](https://github.com/candy999/kuroshio-dns/blob/main/docs/docker.md)。

**其他 Linux、第三方路由器韌體**：`kuroshio-linux-<CPU>.tar.gz`（執行檔＋`data/`），見 [移植指南](https://github.com/candy999/kuroshio-dns/blob/main/PORTING.md)；只要執行檔的話是 `kuroshio-<CPU>`。`SHA256SUMS` 是所有檔案的雜湊值。

**原始碼**：`kuroshio-dns-3.4.0-source.tar.xz`（這個版本的原始碼加上全部依賴套件，可以完全離線編譯；雜湊值在 `SHA256SUMS`）。

## 從 3.3.7 升級

- **OpenWrt**：下載同一個架構的新壓縮檔，解壓後執行 `sh install.sh`，直接覆蓋升級。新開關的預設值就是建議值，不用改設定；兩台都升級後會自動串接。
- **Windows**：停止黑潮 DNS（cmd 視窗輸入 `quit`，或 `kuroshio.exe service stop`），用新的 `kuroshio.exe` 與 `data\` 取代舊的，再啟動。
- **Docker**：`docker compose pull && docker compose up -d`（或 `docker pull ghcr.io/candy999/kuroshio-dns:3.4.0`）。
- **其他 Linux、第三方韌體**：執行檔與 `data/` 一起換；用 UCI 文字設定檔的，升級後執行一次 `kuroshio uci-migrate <UCI 檔>`。
