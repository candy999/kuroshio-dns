黑潮 DNS 3.2.0：重新整理預設過濾清單（加入威脅情資、TWNIC 停止解析名單與兩份國際廣告清單，拿掉會誤擋的清單），並修正 165 反詐騙清單裡約 2,300 個詐騙網域一直沒有被擋的問題。直接覆蓋升級即可，設定與學習資料會保留；你沒動過的預設清單會自動換成新的，改過的一律不動。

- **HaGeZi TIF 精簡版（威脅情資）**：以前列在清單裡的是 TIF 完整版（上百萬條，原始檔 2026-11 實測約 30 MB），太大所以預設關閉，等於沒有國際的惡意網域防護。精簡版約 19 萬條，挑的是真的有人連的惡意網域，現在預設開啟。
- **FutaGuard TWNIC-RPZ**：台灣網路資訊中心（TWNIC）停止解析的網域（盜版影音、詐騙等），台灣多數 ISP 的 DNS 會照這份名單停止解析；黑潮 DNS 走國外上游時也一樣擋下來。
- **OISD small、HaGeZi Light**：國際廣告與追蹤清單，補上中文清單沒涵蓋的國際網站與 App。兩份都是以「不誤擋」為原則維護的精簡版。照上面的順序疊上去實測（2026-11），去掉完全相同的網域後，OISD small 新增約 1.8 萬個網域、HaGeZi Light 約 5.2 萬個（如果把「上層網域已經整個擋掉」也算成重複，分別約 1.7 萬、3.9 萬）。
- **記憶體**：預設清單合計約 37 萬個網域，過濾器本身約 3.3 MB（以前約 1.25 MB；實際記憶體用量依裝置而定）。128 MB 記憶體的路由器照樣能用；記憶體真的吃緊時，記憶體控制會先暫停廣告類清單，165 反詐騙、TWNIC、威脅情資這些保護清單最後才動。
- **Ruddernation 改成預設關閉**：它會擋 Adobe 的授權驗證，正版 Adobe 軟體也會啟用失敗。只想擋 Adobe 遙測的話，a-dove-is-dumb 就夠了。
- **移除 blocklistproject tracking**：2026-07 之後就沒有更新，而且會擋 Spotify 播放、Instagram、Google 安全瀏覽（Safe Browsing）。
- **移除 blocklistproject adobe**：會擋 Adobe 登入。
- **a-dove-is-dumb 改用官方 CDN 網址**（`https://a.dove.isdumb.one/cdn`），內容跟以前的 GitHub 原始檔相同。

## 修正

- **165 反詐騙清單少擋了約 2,300 個網域**：FutaGuard TW165 裡有一批詐騙網域寫成 `||網域/^`（後面多一個空路徑）。以前把它當成「含路徑的網址規則」略過，這些網域其實一直沒有被擋（2026-11-13 實測 2,366 個）。現在空路徑（`||網域/`、`||網域/^`，可以再加 `$important` 這類修飾詞）等同整個網域 `||網域^`；真的有路徑的規則（`||網域/some/path`）在 DNS 層無法套用，照樣略過。

## 預設自訂規則

新安裝時的預設自訂規則多了三條放行規則：

```
@@||crl.microsoft.com^
@@||presence.teams.live.com^
@@||msdk.shopee.tw^
```

- `crl.microsoft.com`：Windows 的憑證撤銷清單。anti-AD 會擋，擋了可能讓 Windows 連線變慢。
- `presence.teams.live.com`：Microsoft Teams 的上線狀態。
- `msdk.shopee.tw`：蝦皮 App（HaGeZi Light 會擋）。

預設自訂規則只在自訂規則檔還不存在時（新安裝）才會放上去，升級不會改你的自訂規則。已經在用的話，需要的請自己加到自訂規則（OpenWrt：LuCI「服務 → 黑潮 DNS → 廣告過濾」的自訂規則；Windows、Docker、其他 Linux：自訂規則檔 `custom-rules.txt`）。

## 既有安裝怎麼搬

只更新「跟 3.1.x 預設值完全相同」的清單項目，你改過的（改了名稱、網址、分類、啟用狀態，或設了保護）一律不動：

- **OpenWrt**：升級時 `/etc/config/kuroshio` 會保留，安裝腳本會逐項檢查：
  - Ruddernation 還是預設的開啟 → 改成關閉；a-dove-is-dumb → 換成官方 CDN 網址；
  - HaGeZi TIF 完整版還是預設的關閉 → 換成精簡版並開啟（你自己打開過完整版的話就保留完整版）；
  - blocklistproject tracking、adobe 還是預設的關閉 → 刪除；
  - 加上 TWNIC-RPZ、OISD small、HaGeZi Light（同一個網址已經有了就不加）；
  - 清單順序沒有自己調整過的話，依新的預設順序排列（自己加的清單接在後面）；調整過就保留你的順序。

  改了什麼會記在系統日誌（`logread -e kuroshio`）。只做一次，之後你刪掉的清單不會再被加回來。
- **Windows、Docker、其他 Linux**：設定檔只記你改過的欄位。沒有 `filter.lists` 的話，自動用新的預設清單；設定頁存檔時寫進去的整份清單如果跟 3.1.x 的預設值完全一樣（同樣的項目、同樣的順序），載入時直接換成新的預設清單，日誌會記一行「過濾清單是舊版預設值，已更新成新的預設清單」。改過任何一項就照你的設定，新的清單請自己在設定頁加上。

## 下載哪一個

**OpenWrt**：在路由器執行 `cat /etc/openwrt_release`，依 `DISTRIB_RELEASE`（OpenWrt 版本）與 `DISTRIB_ARCH`（套件架構）下載 `kuroshio-openwrt-<版本>-<架構>.zip`。

| 平台 | 常見晶片 | 檔名結尾 |
|---|---|---|
| 64 位元 ARM | MediaTek Filogic（MT7981 / MT7986 / MT7988）、MT7622、Qualcomm IPQ807x / IPQ60xx / IPQ50xx、樹莓派 3 | `aarch64_cortex-a53` |
| | Rockchip RK3328 / RK3399 / RK3568 / RK3588（NanoPi R2S～R6S） | `aarch64_generic` |
| | 樹莓派 4、Marvell Armada 7K / 8K | `aarch64_cortex-a72` |
| | 樹莓派 5 | `aarch64_cortex-a76` |
| 32 位元 ARM | Qualcomm IPQ4018 / IPQ4019、Allwinner H3 | `arm_cortex-a7_neon-vfpv4` |
| | Marvell Armada 385（Linksys WRT 系列） | `arm_cortex-a9_vfpv3-d16` |
| | Qualcomm IPQ806x（Netgear R7800 等） | `arm_cortex-a15_neon-vfpv4` |
| MIPS | MediaTek MT7621 / MT7620 / MT7628（小端序） | `mipsel_24kc` |
| | Qualcomm Atheros、Lantiq（大端序） | `mips_24kc` |
| x86 | 軟路由小主機、虛擬機 | `x86_64` |

OpenWrt 24.10 用 `-24.10-` 的（.ipk），25.12 以後用 `-25.12-` 的（.apk）。不知道選哪個：[選硬體、選套件](https://github.com/candy999/kuroshio-dns/blob/main/docs/hardware.md)。

壓縮檔裡有 `kuroshio`、`luci-app-kuroshio` 與一鍵安裝腳本：解壓後把資料夾傳到路由器，執行 `sh install.sh`。腳本會先檢查架構與版本，不符合就告訴你該下載哪一個。裝好後到 LuCI「服務 → 黑潮 DNS」確認設定、按「啟用」。

**Windows 10 / 11**：`kuroshio-windows-x86_64.zip`，單一執行檔，不需要另外安裝 Visual C++ 執行階段。

**Docker**：`docker pull ghcr.io/candy999/kuroshio-dns:3.2.0`，見 [Docker 使用說明](https://github.com/candy999/kuroshio-dns/blob/main/docs/docker.md)。

**其他 Linux、第三方路由器韌體**：`kuroshio-linux-<CPU>.tar.gz`（執行檔＋`data/`），見 [移植指南](https://github.com/candy999/kuroshio-dns/blob/main/PORTING.md)；只要執行檔的話是 `kuroshio-<CPU>`。`SHA256SUMS` 是所有檔案的雜湊值。

## 從 3.1.x 升級

- **OpenWrt**：下載同一個架構的新壓縮檔，解壓後執行 `sh install.sh`，直接覆蓋升級。預設清單會照上面「既有安裝怎麼搬」自動更新。
- **Windows**：停止黑潮 DNS（cmd 視窗輸入 `quit`，或 `kuroshio.exe service stop`），用新的 `kuroshio.exe` 與 `data\` 取代舊的，再啟動。
- **Docker**：`docker compose pull && docker compose up -d`（或 `docker pull ghcr.io/candy999/kuroshio-dns:3.2.0`）。
- **其他 Linux**：執行檔與 `data/` 一起換。
