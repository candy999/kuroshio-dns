# 惡意網站探測網域：每日評測用（3.5.0）。可以留空；有內容時優先，並與抽樣合併。
#
# 用途：判出「有擋惡意網站的 DNS」。這類 DNS 以前評測判不出來（評測網域只有廣告追蹤與成人網站），
#   混在候選裡會被選上；判出之後比照對照組：照常評測、今天不選、不記可疑、不進永久黑名單。
#   也讓對照組（protected.txt）裡 filter=malware 的那幾台判得出來（expectMet）。
#
# 探測網域從哪裡來（3.5.0 F10）：
#   1. 這份檔案（手動指定，最多 8 個）：排最前面，一定參加自我檢查。
#   2. 抽樣（benchmark.probeSample，預設開）：每次評測前，主程式從這台已經下載的惡意類過濾清單
#      （filter.lists 裡 category 是 malware、啟用中、沒有標 probe: false 的；TW165、TWNIC-RPZ、新註冊網域、
#      繞過防護預設不抽）的本機副本抽 40 個，先問一台不過濾的參照確認還解析得到（留最多 20 個）。
#      記憶體吃緊、清單被記憶體控制停用中、沒有本機副本時不抽（不為了抽樣多下載）。repo 不放固定名單。
#   兩者合併（不是二選一）；自我檢查通過的前 12 個拿去問全部候選（抽樣關掉時是前 4 個，跟 A5 一樣）。
#
# 格式：一行一個網域，後面一定要有 probe=malware，並寫出處與確認日期：
#   <網域>  # probe=malware src=<出處> checked=<確認日期>
#   沒寫 probe=malware 的行一律不採用（不小心貼進來的一般網域不會被當成探測）。
#   使用者自己的名單目錄也可以放 probe.txt，跟這份合併。
#
# 判斷（使用者定案）：抽樣開著時，一台候選在有效的探測裡有回答的至少 6 個、而且擋了一半以上才算「有擋惡意網站」；
#   有效的探測不到 6 個時只看對照組、不判斷一般候選。抽樣關掉時照 A5：2 個以上都擋才算。
#
# 手動加的怎麼挑（一定要人工確認）：
#   1. 首選：已經被資安組織或執法單位接管（sinkhole）多年的知名惡意網域。它們解析到接管方的位址、本身無害，
#      而且各家「擋惡意網站」的 DNS 幾乎都列了。
#   2. 次選：過濾服務商或測試組織為了「檢查防護有沒有生效」公布的測試主機名稱。缺點是通常只有那一家擋，
#      過不了「至少 2 家不同經營者的對照組都擋」的自我檢查，只能搭配其他網域。
#   確認方式：在沒有攔截的線路上，不過濾的 A 級上游都解析得到（回一般位址，不是 NXDOMAIN、不是 0.0.0.0）、
#     protected.txt 裡 filter=malware 的至少 2 家不同經營者回封鎖（NXDOMAIN、0.0.0.0）。兩邊結果不一樣才有用。
#   評測每天也會自己檢查一次（對照組沒擋、或不過濾的也多半解析不到 → 那個網域當天不拿來判斷；
#     判出的候選超過一半 → 整段作廢），所以網域失效時不會誤判，只是判不出來。
#
# 注意：評測只對探測網域做 DNS 查詢，不連線、不做憑證驗證。但抽樣抽到的是「還在活動的惡意網域」：
#   線路上的資安設備可能把這台記成「有裝置中毒、在查惡意網域」（每天十幾個）。企業或學校網路建議把
#   benchmark.malwareProbe（UCI malware_probe）關掉；只想停掉抽樣、保留這份檔案的，關 benchmark.probeSample（UCI probe_sample）。
# judge.log 不寫出抽到的網域（只寫數量；要看是哪些用 DEBUG 等級的日誌）。
# 文件與範例裡不寫實際的探測網域（測試用 malware-test.example.com）。
