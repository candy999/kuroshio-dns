# 惡意網站探測網域：每日評測用（3.5.0）。這份名單目前是空的＝惡意網站探測整段不跑，評測跟 3.4.4 一樣。
#
# 用途：判出「有擋惡意網站的 DNS」。這類 DNS 以前評測判不出來（評測網域只有廣告追蹤與成人網站），
#   混在候選裡會被選上；判出之後比照對照組：照常評測、今天不選、不記可疑、不進永久黑名單。
#   也讓對照組（protected.txt）裡 filter=malware 的那幾台判得出來（expectMet）。
#
# 格式：一行一個網域，後面一定要有 probe=malware，並寫出處與確認日期：
#   <網域>  # probe=malware src=<出處> checked=<確認日期>
#   沒寫 probe=malware 的行一律不採用（不小心貼進來的一般網域不會被當成探測）。
#   最多讀 8 個，每次評測用自我檢查通過的前 4 個；有效的不到 2 個時只看對照組、不判斷一般候選。
#   使用者自己的名單目錄也可以放 probe.txt，跟這份合併。
#
# 怎麼挑（一定要人工確認，不能用程式自動產生或直接抄威脅情資清單）：
#   1. 首選：已經被資安組織或執法單位接管（sinkhole）多年的知名惡意網域。它們解析到接管方的位址、本身無害，
#      而且各家「擋惡意網站」的 DNS 幾乎都列了。
#   2. 次選：過濾服務商或測試組織為了「檢查防護有沒有生效」公布的測試主機名稱。缺點是通常只有那一家擋，
#      過不了「至少 2 家不同經營者的對照組都擋」的自我檢查，只能搭配其他網域。
#   3. 不用：還在活動的惡意網域（會變、有風險）。
#   確認方式：在沒有攔截的線路上，不過濾的 A 級上游都解析得到（回一般位址，不是 NXDOMAIN、不是 0.0.0.0）、
#     protected.txt 裡 filter=malware 的至少 2 家不同經營者回封鎖（NXDOMAIN、0.0.0.0）。兩邊結果不一樣才有用。
#   評測每天也會自己檢查一次（對照組沒擋、或不過濾的也多半解析不到 → 那個網域當天不拿來判斷；
#     判出的候選超過一半 → 整段作廢），所以網域失效時不會誤判，只是判不出來。
#
# 注意：評測只對這些網域做 DNS 查詢，不連線、不做憑證驗證。但查這類網域可能被上游或線路上的資安設備記成
#   「這個位址有裝置查惡意網域」；不想要的話把 benchmark.malwareProbe（UCI malware_probe）關掉。
# 文件與範例裡不寫實際的探測網域（測試用 malware-test.example.com）。
